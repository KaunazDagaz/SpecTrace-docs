Тот же раздел начинается словами:

> "Use of Google AI Studio and Gemini API is for developers building with Google AI models for professional or business purposes, not for consumer use."

(Перевод агента: «Google AI Studio и Gemini API предназначены для разработчиков, которые строят решения на моделях Google AI в профессиональных или деловых целях, а не для потребительского использования».)

Сервис по живому URL подпадает под случай из первого предложения:
- Он открыт любому, в том числе пользователям в ЕЭЗ; Литва входит в ЕЭЗ.
- С 29 сентября он вызывает Gemini API с ключом AI Studio проекта `gen-lang-client-0785466808`, как записано в README. Какой ключ лежит в секрете, агент видеть не может.
- У этого проекта по замыслу нет биллинга (REQ-DEP-02, §10.2 плана), поэтому вызовы идут на бесплатной квоте.

`research/decisions.md` (запись от 29 сентября) и TOR 1.6 фиксируют риски живого сервиса — квоту, использование данных, воспроизводимость и стоимость, — но не это ограничение. Записка приводит текст и не даёт юридического толкования. Варианты для студента:

- **(а) Сразу вернуть сервис в офлайн.** Это делает «аварийный выключатель» из README, без пересборки. Офлайн-конфигурация прошла 18 из 18 смоук-проверок 29 сентября (README, раздел Deployment). §10 TOR тогда возвращается к формулировке версии 1.5; строка D4 в §6 её предлагает.
  - После этого нельзя заново запускать `deploy/deploy.sh` в нынешнем виде: он всегда разворачивает живой режим (см. §5).
  - **Это рекомендация агента.**
- **(б) Оставить сервис живым на платных сервисах**, включив биллинг на проекте ключа.
  - Это отменяет бесплатный уровень, на котором построен проект (Blueprint §8, §10.2 плана), и делает платным каждый вызов.
  - Нужны запись о решении, редакция TOR, а для Blueprint §8 — повторное утверждение руководителем.
- **(в) Оставить как есть.** По процитированному тексту это значит работать вопреки условиям провайдера. Не рекомендуется.

**2. Сквозная проверка SPEC-13 неполна.**
- Закоммиченная проверка содержит решения по 2 из 23 тест-кейсов и по 1 из 4 элементов очереди.
- SPEC-13 принимается по "a manual walkthrough of the full RFC 6902 review", а REQ-REV-01 — по "Manual walkthrough of one full document's review".

Варианты:
- **(а) Завершить сквозную проверку до слияния этой записки.** Затем закоммитить новый журнал и заново выполнить `score --reviews`; строка 13.1 в §2 и §4 изменятся вместе с этим.
- **(б) Принять M2 с частично выполненным REQ-REV-01** и перенести сквозную проверку в M3, записав это так, как предлагает строка D1 в §6.

**Подтвердить: бюджетное оповещение** на `spectrace-deploy` (REQ-DEP-02).
- README по-прежнему помечает его как ожидаемое, и ни в одном PR нет снимка экрана, который карточка SPEC-14 требует как доказательство.
- У агента нет доступа к консоли Google Cloud.

## 1. Рабочий сценарий

### По живому URL

Что делает человек вне проекта и что он видит. Каждый шаг сегодня наблюдался — через `smoke-test.sh` или прямым запросом.

1. **Открыть список запусков** по адресу [https://spectrace-5zrm6uxcja-lz.a.run.app][live]. После паузы первый ответ занимает несколько секунд, пока запускается экземпляр; сегодня `/health` ответил за 2,3 секунды. Жёлтый баннер на каждой странице говорит:
   - это публичное демо, которое вызывает модель;
   - документ из закоммиченного кэша воспроизводится без вызова, а любая другая загрузка уходит в бесплатный уровень Gemini через ключ автора;
   - загружать можно только публичные спецификации, и все посетители делят одну суточную квоту;
   - эталонный прогон доступен только для чтения, имена проверяющих заявлены ими самими, а прогоны и решения, сделанные здесь, исчезают при перезапуске экземпляра.
2. **Открыть эталонный прогон** `rfc6902-3ff2234db6aa`:
   - манифест;
   - доля проверенных цитат 77,8%;
   - 12 требований, 23 предложенных тест-кейса и 4 элемента очереди решений.
3. **Открыть его страницу проверки.** На ней:
   - каждое требование в контексте источника, вместе с его тест-кейсами;
   - 5 записанных решений автора, только для чтения.

   Решение, отправленное всё же — из формы или вручную, — отклоняется с кодом 403, и в журнале остаются 5 строк.
4. **Открыть проверенную матрицу**: 11 требований покрыты, 1 пробел; есть выгрузка в Markdown и CSV.
5. **Воспроизвести документ корпуса**: выбрать `rfc6902.txt` в форме нового запуска.
   - Он за секунды воспроизводится из кэша в прогон `rfc6902-3ff2234db6aa` — с тем же ID, что у эталонного прогона.
   - Этот прогон посетитель проверяет сам: ввести имя, затем принять, отредактировать или отклонить; проверенная матрица следует за решениями.
   - Так же воспроизводится `rfc10050.txt`.
6. **Загрузить свой документ**: один текстовый файл UTF-8 не больше 64 КиБ.
   - Он идёт вживую, не чаще десяти запросов к модели в минуту, и расходует суточную квоту ключа.
   - Сегодняшний документ смоук-теста, одно предложение, занял 2 вызова и около 8 секунд.
   - **Именно этого шага касается решение 1 из раздела «Статус».**
7. **Вернуться позже**: прогоны и решения, сделанные по URL, живут только в этом экземпляре, и перезапуск, масштабирование до нуля или новое развёртывание их удаляют.

### Повторное развёртывание

Его выполняет студент из Cloud Shell; агент никогда не запускает `gcloud` на проектах студента:

```
cd ~/SpecTrace-dev && git pull
bash deploy/deploy.sh spectrace-deploy gen-lang-client-0785466808 europe-north1
bash deploy/smoke-test.sh https://spectrace-5zrm6uxcja-lz.a.run.app --live
```

```
gcloud run services update spectrace --project spectrace-deploy --region europe-north1 --remove-env-vars SPECTRACE_OFFLINE --remove-secrets GEMINI_API_KEY --cpu-throttling
bash deploy/smoke-test.sh https://spectrace-5zrm6uxcja-lz.a.run.app
```

**Чувствительность правила сопоставления.** При перекрытии 30% и 70% каждое число каждого плеча совпадает с числом при 50%. Наименьшее перекрытие среди совпавших пар — 100%: каждое найденное утверждение цитирует всё предложение или придаточное вокруг своего эталонного требования. На RFC 6902 порог не важен. Это изменилось бы на документе, где модели цитируют фрагменты, выходящие за границы предложений.

**Цена проверки.**
- **Вызовы и токены.**
  - A: 1 вызов, 7 647 токенов на вход и 1 788 на выход на RFC 6902; 7 930 и 2 220 на RFC 10050.
  - B: 13 вызовов, 11 708 и 3 374 на RFC 6902; 14 вызовов, 12 344 и 4 285 на RFC 10050.
  - Каждое воспроизведение на 100% обслуживается из кэша.
- **Что проверка удержала от реестра конвейера.** 6 из 19 эталонных требований, 31,6 пункта полноты: 94,7% у сырых утверждений против 63,2% у поставленных.
  - Четыре из них — цитаты, которые встречаются в документе дважды.
  - Два — одно предложение, заявленное с двумя прочтениями.
  - Все шесть лежат в очереди решений человека; ни одно не потеряно.
  - На RFC 6902 ни одна цитата конвейера не провалила проверку.
- **В чём проверка отказала базовой линии.** Из 13 её ненайденных цитат 12 имеют сходство 0,90 и выше (мера из [`headline.md`][headline]). Они попадают на 12 эталонных требований, которые не совпали ни с одним найденным утверждением базовой линии. Базовая линия дотянулась до 15 из 19 требований, а засчитано ей 3.
  - Причина, согласно [`error-analysis.md`][ea] §2: одна последовательная правка форматирования — двойные кавычки переписаны в одинарные.
  - Ни одна ненайденная цитата во всём эксперименте не выдумана и не перефразирована.

### Что не работает или работает лишь частично

- **Сквозная проверка неполна**: 2 из 23 кейсов и 1 из 4 элементов. Действием «отредактировать» на эталонном прогоне не пользовался ни один человек: 0 отредактировано.
- **В M2 решение человека по цитате, найденной больше одного раза, не меняет реестр.** 6 удержанных эталонных требований так и остаются удержанными, а единственное решение по очереди в журнале ничего не изменило. Привязку таких цитат error-analysis §10 записывает как находку на потом.
- **«Тестируемо» записывается, но кейса не порождает**, поэтому такое требование остаётся пробелом.
- **Публичный сервис**:
  - не имеет учётных записей;
  - делит одну суточную квоту между всеми посетителями;
  - принимает любую загрузку, и только формулировка страницы удерживает её в пределах публичных спецификаций;
  - ничего не хранит после перезапуска;
  - не воспроизводит из репозитория свои живые прогоны;
  - может ненадолго превысить предел в один экземпляр;
  - с 29 сентября тарифицируется по экземплярам.
- **`deploy/deploy.sh` всегда разворачивает живой режим.** «Аварийный выключатель» переводит работающий сервис в офлайн, но следующий запуск `deploy.sh` снова его оживит. Офлайн-развёртыванию нужна правка скрипта, а она вне границ этой задачи.
- **Баннер, README и `decisions.md` могут преувеличивать использование данных провайдером.** Они говорят, что входные данные "may be used to improve Google's models". Для разработчика в ЕЭЗ условия провайдера применяют условия платных сервисов о данных и к бесплатной квоте: §6, строка D5.
- **NFR-04 по-прежнему не выполнено**: провайдер и модель — константы в [`LlmClientFactory`][factory], как и на M1.
- **Ряд документов отстаёт от системы**: §6, строки D3, D7, D8 и D12.

### 8.2 Какое допущение оказалось неверным

Факты:

- **Эталон.** Blueprint 1.0 ожидал 30–50 эталонных требований. По правилам, зафиксированным заранее, в RFC 6902 их 19 (TOR 1.2).
- **Как ошибается непроверяемый подход.** На RFC 6902:
  - Плечо чата нашло все 18 своих цитат.
  - 13 ненайденных цитат базовой линии — одна привычка форматирования, и 12 из них дотянулись до эталонного требования.
  - Ни одна ненайденная цитата в эксперименте не выдумана и не перефразирована ([`error-analysis.md`][ea], §2 и §3).
- **Проверка необходимости разбиения.** На RFC 6902 она не может сработать: в последней трети нет ни одного эталонного требования (TOR 1.4).
- **Бесплатный уровень.** 29 сентября агент предложил вариант сделать публичный сервис живым, перечислив риски квоты, использования данных, воспроизводимости и стоимости, и студент его выбрал. Агент не проверил условия провайдера, и ограничение для ЕЭЗ было упущено («Статус», решение 1).
- **Оговорка об использовании данных.** Blueprint §4 и баннер исходят из того, что бесплатный уровень может обучаться на входных данных. Для разработчика в ЕЭЗ провайдер вместо этого применяет свои условия платных сервисов о данных (§6, строка D5).
- **Предложение в списке запусков.** Начиная с SPEC-13 оно говорило, что в живом режиме без ключа кэшированные документы по-прежнему запускаются. Это не так. Обнаружилось это только при создании живого режима ([`ba50791`][c-ba50791]).
- **Вставка в `read -rs`.** Предполагалось, что она сохраняет вставленный текст как есть. «Вставка в скобках» (bracketed paste) Cloud Shell обернула ключ управляющими кодами (PR [#17][d17]).
